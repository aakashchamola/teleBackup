# M1: Proof of concept (the spike)

> **Status (2026-11-02):** **Blocked on the phone, a throwaway Telegram group and the owner** (see `docs/STATUS.md`). Written ahead: `tools/make_testkit.sh`, `tools/push_testkit.sh` (not yet run), the Bot API client and setup calls (tested against a fake server), `SecretStore`, the debug-only S-DEV screen and `devCommand`, `FaultInjector`. Nothing in `M1_FINDINGS.md` is answered. TDLib (tasks C, E part) is not started.

**Goal:** prove the risky parts on the owner's real phone before building anything real: bot upload into a topic, a big video through the account, checking Telegram's reply, re-fetching a bot message with the account, deleting files from each kind of folder, and the background service surviving hours with the screen off.

**Done when (ROADMAP):** in a test folder, one photo goes to a topic through the **bot**; one video over 50 MB goes through the **account**; the reply is checked; the file is deleted. And every question in `docs/M1_FINDINGS.md` has an answer, with the decisions written down and the design docs updated.

**Code in M1 is throwaway.** It lives in the debug source set (`app/android/app/src/debug/kotlin/.../spike/`) behind S-DEV buttons, so it never reaches a release build. Keep what proves useful (the TDLib setup, the multipart upload) to rewrite properly in M2/M3.
