# M3: Background upload and notification

> **Status (2026-11-02):** Done and tested on a computer: Bot client, hasher, caption, pacer, reply checks, upload loop, workers, scheduler, controls, notifications, status and warnings, Home. **Not done:** the account client (`TdClient`, `AccountAuth`, `AccountSender`: needs TDLib) and section 9 "On the phone".

## Tasks

### 1. Secrets
- [ ] `SecretStore`: AES-256-GCM key `telebackup.secrets` in Android Keystore; values (bot token, api_id, api_hash, TDLib key) in one encrypted file in the no-backup dir. API: `put(name, value)`, `get(name)`, `remove(name)`, `clearAll()`.
- [ ] `SecretStoreTest` (instrumented).

### 2. Bot client
- [ ] `BotApi` (OkHttp): `getMe`, `getUpdates`, `getChat`, `getChatMember`, `sendMessage`, `createForumTopic`, `sendPhoto`, `sendVideo`, `sendDocument`. DTOs with kotlinx-serialization (`ignoreUnknownKeys = true`).
- [ ] Streaming multipart with a progress-counting `RequestBody`. Timeouts per TELEGRAM.md.
- [ ] Error mapping to `TgError` (TELEGRAM.md table), `migrate_to_chat_id` follow-up.
- [ ] Base URL overridable in debug builds only (for MockWebServer on the device).
- [ ] `BotApiTest` (MockWebServer), including the token-never-logged check.
- [ ] `BotSetup`: the setup calls behind `setBotToken`, `findGroups`, `checkGroup`, `selectGroup`, topic creation. Replace the M2 temporary topic creation.

### 3. Account client
- [ ] `TdClient`: one TDLib client, own handler thread, `suspend fun <T> send(fn): T`, a `SharedFlow` of updates, open/close on demand with an idle timeout (2 min).
- [ ] `AccountAuth`: state flow -> `account.state` setting + `onTelegramState`; bridge calls `accountStart/Phone/Code/Password/ResendCode/Logout`.
- [ ] `AccountSender`: `sendMessage` + wait for `updateMessageSendSucceeded/Failed` by `old_message_id`; progress from `updateFile`; cancel on stop; error mapping; ids to Bot API form (`TdIds`).
- [ ] `TdIdsTest` with the values found in M1.

### 4. Upload pieces
- [ ] `Hasher` (streaming SHA-256, 1 MB buffer, cancellable).
- [ ] `CaptionBuilder` + tests.
- [ ] `Pacer` + tests.
- [ ] `Verifier.checkReply` + tests (rules from TELEGRAM.md + M1 Decision 3).
- [ ] `UploadLoop`: the loop in HOW_IT_WORKS section 5 as a plain class (no Android types), so `UploadLoopTest` drives it with fakes.
- [ ] `UploadWorker`: `CoroutineWorker` wrapping `UploadLoop`; `setForeground(ForegroundInfo(1, notification, FOREGROUND_SERVICE_TYPE_DATA_SYNC))`; `getForegroundInfo()` for expedited fallback; maps `isStopped`/`stopReason` to `RUN_STOPPED` events; catches `ForegroundServiceStartNotAllowedException` -> `retry()`.
- [ ] `UploadScheduler`: enqueue `upload` (KEEP) with the right network constraint; `retry-at` for the earliest backoff; re-enqueue on account login, on resume, on app start if queue not empty.
- [ ] Manifest: `<service android:name="androidx.work.impl.foreground.SystemForegroundService" android:foregroundServiceType="dataSync" tools:node="merge" />`.
